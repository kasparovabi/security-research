# lean-ctx: the ctx_proof filename was not confined, so exports could be written outside the path jail

**Advisory:** [GHSA-pv78-9chr-hj3c](https://github.com/yvgude/lean-ctx/security/advisories/GHSA-pv78-9chr-hj3c) (published 2026-10-29)
**Package:** `lean-ctx` (crates.io) and `lean-ctx-bin` (npm), affected `< 3.12.0`, patched in 3.12.0
**Weakness:** CWE-22, CVSS 3.1 `AV:L/AC:L/PR:L/UI:N/S:U/C:N/I:L/A:L` (Medium, 4.4)

[lean-ctx](https://github.com/yvgude/lean-ctx) confines what MCP tools read and write to the project through a PathJail. `ctx_read` and `ctx_patch` outside the project are refused, and `ctx_handoff` refuses a `filename` that escapes it.

## Root cause

`ctx_proof` with `action: export` writes a context proof, a JSON document generated by lean-ctx, to `<project>/.lean-ctx/proofs/`. It accepts an optional `filename` from the caller.

- `write_project_proof` in `core/context_proof.rs` built the path with `proofs_dir.join(name)` and wrote it atomically.
- Rust's `Path::join` with an absolute `name` discards the base, `..` components were not rejected, and the result was never checked against the jail.

So a caller could create or replace any file the server process could write. The content stays lean-ctx's own JSON, which limits it mostly to clobbering files. In agent setups the caller can be steered by instructions inside untrusted content the agent reads, and where the jail is the write boundary that matters.

While checking the other tools that take a path, I found that `ctx_knowledge` OKF export wrote a directory of Markdown files to a path outside the project, with bodies taken from stored facts, and OKF import read a facts file outside the project that `ctx_read` would have refused. `ctx_agent` already checked its `filename` and was not affected.

## Fix

Pull request [#2150](https://github.com/yvgude/lean-ctx/pull/2150), squashed as [`0c9134e`](https://github.com/yvgude/lean-ctx/commit/0c9134e880d299c9a9c04326015c0941c8fb5023) and released in 3.12.0:

- [`c2f7f4f`](https://github.com/yvgude/lean-ctx/pull/2150/commits/c2f7f4fa4764da0220170f2130be0de897ed6c23), the patch proposed in the advisory's temporary private fork, accepts only a plain file name for `ctx_proof` and keeps `ctx_knowledge` OKF export and import paths inside the project, with regression tests for each.

A relative OKF `path` now resolves against the project root instead of the working directory.

## What I took from it

- `Path::join` (and `os.path.join` in Python) silently drops the base when the second argument is absolute. A file name from a caller has to be checked as a single normal component before it is joined.
- A jail only holds if every writer goes through it. The tools that already checked their paths made the unchecked ones easy to find by comparison.
- Once one writer escapes, the readers and writers next to it are worth checking too. Here that found the `ctx_knowledge` paths.

Thanks to the lean-ctx maintainer for fixing all three paths and publishing the advisory with 3.12.0.
